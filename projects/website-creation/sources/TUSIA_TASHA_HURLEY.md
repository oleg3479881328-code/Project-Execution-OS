## Why It Matters To Website Creation

Tusia/Tasha is a second real client implementation of the structured website-production model, useful for testing which Olga-derived patterns generalize beyond the original project.

## Reusable Patterns Already Proven/Adopted In The Project

- one canonical structured Knowledge Database rather than scattered operational truth;
- stable entity IDs, crosswalk, evidence, relationships, media and QA layers;
- Page Queue as the explicit contract between knowledge/research and website generation;
- URL/redirect registry treats existing public URLs as assets;
- Page Factory consumes approved canonical IDs/queue state instead of doing parallel ad-hoc research;
- pipeline:
  `sources -> identity resolution -> Knowledge DB -> SEO Production Queue -> QA gates -> Page Factory -> preview -> client validation -> technical QA -> explicit release -> verification -> feedback to Knowledge DB`;
- existing website shell/navigation/transitions should be preserved rather than replaced merely because a Page Factory exists;
- preview/staging is not production approval;
- no invented facts and no speculative identity merges;
- media is first-class and provenance-aware;
- generic AI copy is not an acceptable production default;
- AI may structure/edit/transform first-party source material, but public story/content should be grounded in real evidence and guided by the client's own voice/reference;
- do not push bulk SEO/editorial workload back onto the client;
- validate one complete real page/content experience before mass generation.

## Current Pilot Principle

Before broad venue/wedding scaling, build one complete real-wedding pilot from:
1. real gallery/selected photos;
2. client-authored writing/page reference showing desired voice/presentation;
3. real first-party story/ceremony/couple material.

The system should then produce one finished preview for client validation, including SEO/AEO work under the hood, rather than delivering fragments requiring extensive rewriting.

## Generalization Value

This source strengthens several Website Creation principles:

- client workload is a production constraint;
- structured automation must preserve brand voice, not merely facts;
- Page Factory and Knowledge Database should be separated by an explicit queue/gate;
- broad automation should follow a validated representative pilot;
- adding programmatic content should integrate with the existing site experience rather than automatically replacing it.

## Boundary

Do not copy Tasha-specific people, weddings, venue facts, client communications or queue state into generic Website Creation standards. Follow the canonical Tusia project for live state.
