## Important Generalized Lessons Captured

- Existing Solution First.
- Separate facts/data from rendering.
- Donor-first design, then normalize/adapt rather than blind clone.
- Preserve stable entity IDs, source evidence, publishability and URL lineage.
- Immutable masters vs traceable delivery assets.
- Safe editor/CMS with bounded client editing.
- Puck + isolated non-destructive image editing is a proven internal donor.
- Explicit staging/release states; build/deploy alone is not published.
- PR/CI/deploy/live-QA chain for code-based production.
- SEO/canonical/schema/sitemap/indexing/image SEO are production contracts, not afterthoughts.
- Programmatic pages require real entity/evidence/publishability gates.
- Existing public URLs are assets; preserve or redirect deliberately.
- Generic AI copy is not an acceptable client-facing default when voice/real story material exists.
- Validate one representative real page/pilot before broad automation scale.
- Measure end-to-end production latency and real search/conversion outcomes.
- Repeated website work should become deterministic algorithms and reusable capabilities.

## Important Evidence Boundary

The Prewitt Duda vs 10Web benchmark packet is prepared, but the recorded project state does not show the actual vendor-generation shootout completed. Do not invent a winner.

The high-value/current consolidation is complete enough for Website Creation to function as the default website re-entry project. However, long-tail historical Drive duplicates, legacy `WEB` folders, backups and every old chat artifact have not been exhaustively normalized one-by-one. Preserve this boundary rather than claiming false completeness.

## Maintenance Rule

Any newly discovered website-creation artifact must be added to `SOURCE_REGISTRY.md` or `TOOL_DONOR_REGISTRY.md` under the narrowest category and marked current/canonical vs donor vs history/legacy. Do not create parallel indexes unless scale genuinely requires a child router.
