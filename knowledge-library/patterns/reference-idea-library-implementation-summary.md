## Reusable pattern

External references should flow through a controlled promotion path:

`IDEA -> RESEARCH -> CONCLUSION -> DISCUSS -> DECIDE -> RECORD`

Captured material is not active system knowledge automatically.

Strong ideas may later become:

- reusable patterns;
- project decisions;
- project tasks;
- central skills;
- execution standards;
- CKL entries;
- Codex handoff packets.

## Strong reusable sub-patterns

### Source-linked reference capture

Every durable item should preserve original source, verification sources, alternatives/risks, related internal artifacts, and one next action.

### Graph Memory Control Layer

Graph memory should generate useful work proposals, not merely show relationships.

Formula:

`graph memory = source-linked decisions + reusable patterns + project gaps + work proposals`

### Opportunity Graph Engine

Detect missing skills, docs, reusable patterns, output contracts, stale decisions, repeated errors, weak links, and orphan nodes.

### Editorial Graph Agent Workflow

`graph detects gap -> console builds brief -> agent drafts -> human approves -> repository stores -> graph updates`

### Agent Artifact Workspace

Agents should produce inspectable artifacts, not only text.

### Skill-as-Folder

Reusable skills should live as versioned folders with contracts, examples, constraints, and self-checks.

### Local Daemon Control Layer

Agent execution should be constrained by project root, allowlists, dry-run, logs, diffs, approvals, and reproducible metadata.

### Codex Bounded Execution Workflow

Codex tasks should be narrow, isolated in worktrees, self-validating, diff-reviewed, and approval-gated.

### Kanban Agent Orchestration Standard

Kanban cards can become controlled multi-agent pipelines based on roles, states, contracts, artifacts, and gates.

### External API Skill Gateway

External API actions should go through auth checks, allowed-action checks, previews, approvals, logs, and readable results.

### State Bridge Reasoning Pattern

Move from current state to target state through explicit bridge steps and consistency checks.

Load this candidate when:

- designing an idea/reference intake system;
- deciding how to promote references into central knowledge;
- designing graph-memory or opportunity-engine behavior;
- creating coding-agent control standards;
- building multi-agent orchestration;
- connecting agents to external APIs.

## Do not load when

- answering a small unrelated factual question;
- doing a narrow micro-task with no reference capture or agent workflow relevance;
- the current project already has a narrower active standard.

## Risks

- premature automation;
- storing speculative patterns as active rules;
- turning the graph into a dense useless web;
- losing source links;
- confusing reference intake with project source of truth;
- overbuilding UI, Neo4j, crawlers, or autonomous memory before manual pain exists.

## Adaptation notes

Keep the MVP manual and Markdown-first.

Automate only after repeated friction is visible.
