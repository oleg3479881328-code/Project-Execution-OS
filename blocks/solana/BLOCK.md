# Solana Block

## Purpose

Provide a reusable Project Execution OS domain layer for Solana product research, dApp architecture, program development, wallet flows, tokens, payments, DeFi/NFT patterns, security review, monetization, and implementation handoff.

This block is for recurring Solana and Web3 product work, not for speculative trading advice.

## Status

`candidate`

This block is research-backed but remains candidate until validated on a real Solana project from concept through devnet or production-ready review.

## Core Principle

Solana work must be product-first, security-first, and existing-solution-first.

Do not start by inventing custom on-chain architecture.

Start by identifying the product surface, existing programs/protocols, wallet flow, account model, transaction path, security risks, and whether on-chain code is actually needed.

## When To Use

Use this block for:

- Solana dApp ideas;
- wallet-connected websites;
- token/NFT/product architecture;
- Solana payments;
- Anchor program development;
- Solana client apps;
- SPL Token or token-extension decisions;
- DeFi or marketplace research;
- Solana AI agent/payment ideas;
- program security review;
- implementation handoff for Solana builders.

## When Not To Use

Do not use this block for:

- investment or trading calls;
- price prediction;
- memecoin promotion;
- instructions to scam, rug, phish, drain wallets, bypass consent, or exploit users;
- private key handling outside secure wallet/key-management boundaries;
- legal, tax, or securities conclusions without qualified professional review.

## Boundary

This block stores reusable domain knowledge only.

Do not store seed phrases, private keys, API secrets, customer wallet data, project-specific treasury data, or confidential business logic in this block.

Keep unstable external facts in dated research reports or references, not as permanent rules.

## Final Rule

The best Solana design is the smallest safe product path: reuse proven programs and tooling where possible, keep sensitive logic off-chain unless on-chain execution is necessary, and review security before value moves.
