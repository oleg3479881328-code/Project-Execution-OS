# Logic Block

## Purpose

This block gives `Project Execution OS` one reusable reasoning layer for logic, argument structure, cause-and-effect analysis, fallacy detection, definition discipline, and decision-quality review across projects.

It helps an agent separate time order from causation, facts from assumptions, examples from rules, correlation from explanation, and persuasive language from valid reasoning.

## Status

`candidate`

## When To Use

Use this block when the task involves:

- explaining or teaching logic concepts;
- distinguishing sequence, correlation, causation, condition, implication, evidence, and conclusion;
- analyzing an argument, claim, debate, plan, or decision for logical strength;
- detecting fallacies, hidden assumptions, contradictions, circular reasoning, false dilemmas, or unsupported conclusions;
- building a reasoning checklist for a project, product, legal discussion, business idea, research task, or agent response;
- turning a vague idea into clear premises, conclusion, test, and decision rule;
- improving agent behavior where reasoning mistakes could cause bad execution.

## When Not To Use

Do not use this block for:

- ordinary factual lookup with no reasoning issue;
- mathematical proof work that belongs in a more specialized math workflow;
- legal conclusions without using the relevant legal block and source hierarchy;
- psychology, persuasion, or negotiation work unless the active problem is argument validity;
- replacing domain-specific review with generic logic language;
- creating a large philosophy encyclopedia inside the central OS.

## Core Rule

Do not confuse order, association, explanation, and proof.

A valid logic pass should connect:

`claim -> terms -> premises -> evidence -> inference -> conclusion -> alternatives -> test -> confidence -> action`

If a conclusion depends on a missing premise, weak evidence, or an untested alternative explanation, the reasoning is incomplete.

## Required Reading Inside This Block

Open only the smallest relevant path:

1. `blocks/logic/REFERENCES.md` when source anchors or terminology are needed.
2. `blocks/logic/VALIDATION_BACKLOG.md` when turning logic ideas into reusable checks, examples, or agent tests.

Add narrower files only after repeated use proves they are needed.

## Typical Modes

This block may route work into:

- definition clarification;
- cause-and-effect review;
- argument mapping;
- fallacy detection;
- assumption extraction;
- contradiction check;
- decision-rule construction;
- evidence-strength review;
- project-plan sanity check;
- agent-output reasoning review;
- educational explanation of logic concepts.

## Typical Outputs

Typical outputs:

- clean definition pair or comparison;
- premise-conclusion map;
- assumption list;
- causation vs sequence distinction;
- fallacy label with plain-language explanation;
- stronger rewritten argument;
- decision checklist;
- confidence note;
- recommended next test or evidence needed.

## Boundary

This block stores the reusable logic layer.

Keep project-specific claims, private facts, legal facts, medical facts, financial assumptions, and execution decisions in the target project or the relevant domain block.

This block may improve reasoning across domains, but it does not replace domain evidence or current-source verification.

## Final Rule

Make reasoning inspectable before making the conclusion stronger.
