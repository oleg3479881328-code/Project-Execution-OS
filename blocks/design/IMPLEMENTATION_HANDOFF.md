# Implementation Handoff

## Purpose

Make website design packages ready for frontend build work.

## Core Rule

A design package is complete only when the builder understands the page, sections, components, responsive behavior, and content rules.

## Required Package

Include:

- page goal;
- target user;
- page list;
- section order;
- component list;
- mobile behavior;
- desktop behavior;
- UI states;
- content rules;
- asset needs;
- build notes.

## Section Notes

For each section define:

- name;
- purpose;
- content;
- layout;
- components;
- action;
- mobile behavior.

## Component Notes

For each component define:

- name;
- variants;
- content fields;
- states;
- interaction behavior;
- data source if any.

## Responsive Notes

Define how the design changes across:

- mobile;
- tablet when needed;
- desktop;
- wide screen when needed.

Avoid designs that only work at one screenshot size.

## Content Notes

Clarify:

- final copy vs placeholder copy;
- maximum text lengths;
- image requirements;
- icon requirements;
- dynamic content rules.

## Stack Fit

Check whether the design fits the selected site stack.

Examples:

- static landing page;
- Next.js SaaS;
- Astro portfolio;
- CMS-driven site;
- dashboard app.

## Final Rule

If the builder must invent layout, states, and responsive behavior, the handoff is incomplete.
