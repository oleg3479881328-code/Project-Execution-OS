# Landing Page Patterns

## Purpose

Provide reusable landing-page structures for conversion-focused website work.

## Core Rule

A landing page is not a poster. It is a guided decision path.

Every section must help the visitor answer:

1. What is this?
2. Is it for me?
3. Why should I believe it?
4. What do I do next?

## Default Landing Structure

1. Hero
2. Problem
3. Solution
4. Benefits
5. How it works
6. Proof
7. Features
8. Use cases
9. Pricing or offer
10. FAQ
11. Final CTA

Do not use every section automatically. Use the smallest sequence that supports the conversion goal.

## Hero Pattern

Required elements:

- clear promise;
- target audience signal;
- product category;
- primary CTA;
- secondary CTA or proof link when useful;
- visual demonstration or strong product image.

Weak hero signs:

- vague slogan;
- no audience;
- no concrete result;
- CTA is hidden;
- visual does not explain the product.

## Problem / Pain Pattern

Use when the visitor may not yet feel the urgency.

Good structure:

- current painful situation;
- cost of doing nothing;
- simple recognition language;
- transition into solution.

Avoid overdrama. The problem must feel true, not manipulative.

## Benefits Pattern

Benefits explain outcomes. Features explain mechanics.

Good benefit section:

- 3 to 5 benefit cards;
- each benefit is outcome-first;
- each card has concrete supporting detail;
- visual hierarchy makes scanning easy.

## How It Works Pattern

Use when the product needs comprehension before trust.

Default structure:

1. Connect or start
2. Configure or import
3. Get result

Keep to 3 steps unless the product truly needs more.

## Proof Pattern

Proof can include:

- testimonials;
- customer logos;
- metrics;
- before/after;
- screenshots;
- case studies;
- founder credibility;
- third-party mentions.

If no proof exists, use product transparency, demo screenshots, or honest beta framing. Do not fake proof.

## Pricing / Offer Pattern

Pricing must answer:

- what do I get;
- who is this plan for;
- what is the billing period;
- what happens after trial;
- why this is worth the price.

Avoid clever pricing UI if it hides the decision.

## FAQ Pattern

Good FAQ handles real objections:

- cost;
- setup effort;
- cancellation;
- data/privacy;
- integrations;
- who it is not for.

Do not use filler questions.

## CTA Pattern

Every CTA should be specific.

Better:

- Start free
- Create my first card
- Generate landing page
- Book demo
- See examples

Worse:

- Learn more
- Submit
- Click here

## Final Rule

A landing page is complete only when each section has a reason to exist and supports a specific visitor decision.
