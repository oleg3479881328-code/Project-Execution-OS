# Motion and Animation

## Purpose

Define when motion improves a website and when it becomes noise.

## Core Rule

Motion must explain, guide, or reward. It must not distract from the user path.

## Good Uses of Motion

Use motion for:

- showing state change;
- guiding attention;
- explaining product workflow;
- making transitions feel natural;
- confirming successful actions;
- revealing content progressively.

## Bad Uses of Motion

Avoid motion when it:

- slows comprehension;
- hides important content;
- makes the page feel unstable;
- competes with CTA;
- exists only because the tool can generate it.

## Landing Page Motion

Good patterns:

- subtle hero entrance;
- product screenshot reveal;
- step-by-step workflow animation;
- testimonial carousel only when controlled;
- CTA hover feedback.

Avoid:

- too many scroll effects;
- moving backgrounds behind important text;
- animations that delay reading.

## SaaS Product Motion

Good patterns:

- loading skeletons;
- state transitions;
- drawer or modal transitions;
- optimistic action feedback;
- progress indicators.

## Microinteractions

Use for:

- button feedback;
- form validation;
- save confirmation;
- copy-to-clipboard;
- upload progress;
- plan upgrade confirmation.

## Performance Rule

Animation must not make the page feel heavy.

Review:

- mobile performance;
- layout shift;
- CPU-heavy effects;
- unnecessary animation libraries.

## Accessibility Rule

Support reduced-motion behavior when motion is significant.

## Final Rule

Motion is part of UX. If it does not help the user understand or act, remove it.
