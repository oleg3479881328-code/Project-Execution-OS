# Section Library

## Purpose

Provide reusable website sections that agents can compose into buildable pages.

## Core Rule

Sections are not decoration. Each section must serve a user decision, trust need, or conversion step.

## Core Sections

### Hero

Use to state the primary promise and next action.

Must include:

- product/category clarity;
- target audience cue;
- concrete promise;
- primary CTA;
- visual or proof cue.

### Problem

Use to create recognition.

Must include:

- current situation;
- pain or inefficiency;
- cost of not solving;
- bridge to solution.

### Solution

Use to explain the product direction.

Must include:

- what the product does;
- how it changes the situation;
- why it is simpler or better.

### Benefits

Use to sell outcomes.

Good count:

- 3 to 5 cards.

Each card:

- outcome headline;
- concrete explanation;
- optional icon or visual.

### Features

Use to explain capabilities.

Group features by user job, not engineering module.

### How It Works

Use to make the path believable.

Default:

1. start or connect;
2. configure or create;
3. get result.

### Use Cases

Use when there are multiple audiences or contexts.

Each use case:

- audience;
- scenario;
- result.

### Social Proof

Use to reduce trust friction.

Can include:

- testimonials;
- logos;
- numbers;
- case studies;
- screenshots;
- public references.

### Pricing

Use when the page needs a buying decision.

Must include:

- plan names;
- target user per plan;
- included value;
- limits;
- CTA;
- billing clarity.

### FAQ

Use to answer objections.

Good FAQ is objection-first, not filler.

### Final CTA

Use to close the decision path.

Must repeat the main action and reduce anxiety.

## Product Sections

### Demo Section

Use when product comprehension needs visual evidence.

### Before / After

Use when transformation is clear.

### Comparison Table

Use when replacing an existing behavior or competitor.

### Integration Section

Use when workflow fit matters.

### Security / Privacy Section

Use when user data, payments, teams, or AI are involved.

### Roadmap / Coming Soon

Use carefully. Do not use future promises as a substitute for current value.

## Content Sections

### Blog Preview

Use when content marketing matters.

### Resource Library

Use for education, templates, or downloads.

### Case Study Preview

Use when proof needs depth.

## Final Rule

Compose pages from sections based on user path, not from a generic template checklist.
