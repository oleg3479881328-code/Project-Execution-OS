# Security and Compliance

## Purpose

Define safe handling rules for tax and accounting workflows.

## Core Rule

The reusable block stores process knowledge only. Do not store personal tax documents, bank statements, payroll exports, identity numbers, account credentials, or final filings inside the reusable block.

## Data Handling Rules

Keep sensitive records in the approved secure project layer.

Use references and checklists in reusable documents instead of copying confidential data.

Apply least-privilege access to accounting tools, payroll systems, portals, shared folders, and integrations.

Use separate accounts and access roles where the tool supports them.

Record who has access, why access is needed, and when access should be removed.

## Credential Rules

Do not place passwords, secret keys, recovery codes, or portal credentials in repository files, issue comments, chat logs, or reusable templates.

Use an approved password manager or secret-management method.

## Document Rules

For each secure document package, keep:

- document category;
- owner;
- tax year or period;
- source;
- received date;
- storage location;
- review status;
- retention decision.

## Tool Review

Before adopting a tool, review:

- access roles;
- authentication options;
- export capability;
- change history;
- backup and recovery options;
- integration permissions;
- offboarding path;
- current official documentation.

## Boundary

This file is a reusable safety layer, not a substitute for a full security assessment or professional compliance review.
