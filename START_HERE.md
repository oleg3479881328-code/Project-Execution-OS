# START HERE — Project Execution OS

## Purpose

This is the single stable global entrypoint into `Project Execution OS` for every project, agent, client and working interface.

Its job is intentionally minimal:

1. enter the system through this file;
2. open the current internal router;
3. follow the smallest relevant route for the active work;
4. continue through as many router/index layers as necessary until the relevant canonical project or content node is reached.

## Internal Router

Open:

`docs/ROUTER.md`

## Recursive Routing Principle

Routing depth is not fixed.

A router may point to another router, registry, index, project entrypoint, domain node, collection index, or canonical content node. Those nodes may route onward again.

Use one level when one level is sufficient. Use ten or one hundred levels when the real information architecture requires them.

Each level should expose navigation, not duplicate the content behind it.

## Interface Rule

ChatGPT Projects, Codex, Claude, DeepSeek, local models and future AI clients are working interfaces, not canonical project memory.

When an interface needs a stable bootstrap instruction or attached pointer, it should point to this global `START_HERE.md`, not to a project-specific duplicate entry system.

Project identity and context are resolved through routing and durable external sources of truth.

## Boundary

Do not store operating rules, project-storage decisions, workflow details, tool procedures, architecture, agent logic, execution instructions, project state or the growing internal route catalogue in this file.

## Final Rule

This file is the one stable global door.

`docs/ROUTER.md` is the first live internal map.

From there, routing may recurse without an artificial depth limit until the smallest relevant canonical node is reached.
