# Knowledge Library Access Setup On Windows

## Purpose

This guide sets up the first local access layer for the `Project-Execution-OS` knowledge library using:

`GitHub -> Obsidian -> Quartz`

## Verified Prerequisites

Verified in the executor environment on June 4, 2026:

- official Quartz 5 docs require `Node` `v22+` and `npm` `10.9.2+`;
- the tested environment had `node v24.13.0`;
- the tested environment had `npm 11.6.2`;
- `Obsidian` was already installed and reused instead of reinstalling it.

Official Obsidian help states that an existing local folder can be opened directly as a vault.

## Folder Roles

- `Project-Execution-OS\` = authoring repository and source of truth
- `Project-Execution-OS-Library-Portal\` = local Quartz portal scaffold

Do not edit publishable source material inside the Quartz `content/` folder. That folder is regenerated by sync.

## 1. Open The Repository In Obsidian

1. Start `Obsidian`.
2. Choose `Open folder as vault`.
3. Select the local folder where you cloned `Project-Execution-OS`.
4. Confirm the vault opens successfully.

Expected result:

- the repository is browsable as one vault;
- Obsidian creates or reuses `.obsidian/` in the repository root;
- Markdown files remain plain files in the Git repository;
- `.obsidian/` stays local and is ignored by Git.

## 2. Sync Only Approved Library Content Into Quartz

From the repository root run:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\sync-public-library-to-quartz.ps1
```

Expected result:

- `Project-Execution-OS-Library-Portal\content\` is rebuilt;
- only allowlisted files are copied;
- a generated landing page is written to `content\index.md`.

## 3. Install Portal Dependencies

If the portal was freshly cloned and dependencies are missing:

```powershell
Set-Location .\Project-Execution-OS-Library-Portal
npm ci
```

## 4. Preview The Portal Locally

From `Project-Execution-OS-Library-Portal\` run the tested command:

```powershell
node .\quartz\bootstrap-cli.mjs build --serve --port 8085 --wsPort 3005
```

Expected local preview address:

`http://localhost:8085/`

Technical note:

- the direct `node .\quartz\bootstrap-cli.mjs ...` invocation was verified successfully in the tested environment;
- `npx quartz ...` may also work in other environments, but it hit a local ESM resolution issue during this validation pass.

## 5. Verify The Boundary

Check that the rendered explorer and searchable content contain only the approved starter set.

At minimum verify that these areas do not appear:

- `logs/`
- `projects/`
- `skills/`
- unrelated `docs/`
- private workflow material

The boundary is enforced by `docs/KNOWLEDGE_LIBRARY_ALLOWLIST.json` and the sync script, not by memory.

## 6. Update Workflow

When approved public content changes:

1. edit the source Markdown in `Project-Execution-OS`;
2. if needed, update `docs/KNOWLEDGE_LIBRARY_ALLOWLIST.json`;
3. rerun the sync script;
4. rerun Quartz preview or build.

## 7. Future Public Deployment

Public deployment is intentionally deferred.

Before any deployment:

- replace the placeholder Quartz site metadata as needed;
- review every allowlisted file again;
- confirm the portal build output contains no internal material;
- then attach a hosting target such as GitHub Pages or Cloudflare Pages in a separate step.

## 8. Optional Separate GitHub Repository

The local portal scaffold exists at:

`Project-Execution-OS-Library-Portal\`

If you want to publish that scaffold into its own private GitHub repository later, run this from inside the portal folder:

```powershell
gh repo create oleg3479881328-code/Project-Execution-OS-Library-Portal --private --source=. --remote=origin --push
```

This creates a separate repository for the portal code without changing public site hosting.

## 9. Rollback

To roll back the access layer without touching canonical knowledge files:

1. stop the Quartz preview process;
2. remove files from `docs/KNOWLEDGE_LIBRARY_ALLOWLIST.json` if they should no longer appear;
3. rerun the sync script;
4. optionally remove the local `Project-Execution-OS-Library-Portal` folder.
