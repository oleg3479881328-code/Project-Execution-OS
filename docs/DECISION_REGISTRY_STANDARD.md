# Decision Registry Standard v1

## Purpose

This standard defines how projects preserve important decisions without losing them inside chat.

## Default Location

Each project should maintain a decision registry when project choices begin to accumulate.

Recommended file:

`project-library/DECISION_REGISTRY.md`

## Record Format

Each decision entry should include:
- date;
- decision;
- reason;
- evidence or source;
- status;
- consequences or follow-up.

## When To Use

Use a decision registry when:
- the project has recurring tradeoffs;
- several alternatives were considered;
- future sessions will need to understand why something was chosen;
- implementation depends on a settled decision.

## Rule

Do not leave important project decisions only in chat.
